# AGENTS.md — 嘉義市咖啡廳 LLM Wiki 運作手冊

本檔案是本知識庫（LLM Wiki）的運作規範與 Schema 定義。
Agent 在處理任何檔案、攝取（Ingest）來源、回答查詢（Query）或執行維護（Lint）時，必須嚴格遵守本規範。

---

## 1. 核心理念與三層架構

依據 Karpathy 的 LLM Wiki 模式：
1. **Raw Sources (`raw/`)**：
   - 存放原始資料（部落格食記 Markdown、IG 貼文純文字、官方公告截圖轉錄等）。
   - **永遠唯讀（Immutable）**：Agent 只能讀取，嚴禁修改或刪除原始檔案。
2. **The Wiki (`cafes/`, `topics/`, `syntheses/`, `index.md`, `log.md`)**：
   - 由 Agent 產出並全權維護的結構化知識層。
   - 所有實體頁與主題頁必須高度互連，使用標準 `[[WikiLinks]]`。
3. **The Schema (`AGENTS.md`)**：
   - 即本檔案，定義資料格式、評估標準與工作流程。

---

## 2. 目錄結構規範

```text
LLM Wiki Note/
├── AGENTS.md                  # 本手冊
├── index.md                   # 全站目錄與快速檢索總表（依行政區/特色分類）
├── log.md                     # 時間序列紀錄（append-only）
├── raw/                       # 原始來源檔案（如 IG 貼文、部落格備份）
├── cafes/                     # 店家實體頁（每家店一個獨立 .md）
├── topics/                    # 概念、風格、甜點、豆種主題頁
└── syntheses/                 # 跨店橫向比較、咖啡散策地圖、專案推薦
```

## 3. 店家實體頁規格 (`cafes/[店家名稱].md`)

每篇店家頁**必須**包含符合 Obsidian **Dataview** 外掛讀取的 YAML Frontmatter，並依序包含標準章節。

### 3.1 YAML Frontmatter 欄位定義

```yaml
---
title: 店家名稱（如：霜空珈琲）
aliases: [別名, 英文名]
district: 東區 | 西區 | 周邊鄉鎮
address: 嘉義市...
google_maps_url: 
business_hours: 平日 12:00-18:00、假日 12:00-19:00
closed_days: 週三、週四（或不定休，以 IG 公告為主）
min_consumption: 每人一杯飲品 | 金額低消約 150-250 元
avg_cost: 約 200-350 元/人
time_limit: 不限時 | 客滿限時 90 分鐘 | 平日不限時/假日 2 小時
quiet_level: 5  # 1~5 分（5 最安靜/輕聲細語，3 一般交談，1 熱鬧吵雜）
old_house_vibe: 5  # 1~5 分（5 完整日式木造/古蹟級老宅，1 現代商用空間無老屋感）
coffee_quality: 5  # 1~5 分（5 自家烘焙高水準/單品強烈，3 義式配方一般，1 附屬副業）
dessert_quality: 5 # 1~5 分（5 專門級手工甜點/必吃，3 普通甜點，1 無甜點）
power_outlets: 多 | 部分座位 | 無
wifi: 有 | 無 | 不明
pets_friendly: 否 | 是（需牽繩/推車）
tags:
  - cafe
  - 嘉義市/東區
  - 老屋老宅
  - 手沖單品
  - 招牌布丁
  - 限時規範
last_updated: 2026-11-22
---
```

### 3.2 內文必備章節

1. **店家一句話特色 (TL;DR)**：用 1~2 句話概括其代表性特質與記憶點。
2. **6 大關鍵維度評析**：
   - **價格與低消條件**：具體記錄飲品/甜點價格區間、低消形式（是否硬性綁飲料？甜點能否折抵？）。
   - **空間與老屋氛圍**：老屋年代、建築工法（日治檜木、磨石子、紅磚、閣樓）、座位配置、採光、適合單人還是聚會。
   - **入座時限與座位環境**：可入座多久？平日/假日規範差異？插座與筆電工作友善度。
   - **安靜程度與聲響氛圍**：環境音量、店家對交談音量的規定（是否有輕聲細語禁令？）、音樂風格。
   - **咖啡風味水準**：自家烘焙、擅長焙度（淺焙/中焙/深焙）、是否有阿里山在地特色豆、手沖水準、義式奶咖表現。
   - **甜點水準與招牌必點**：招牌甜點（布丁、巴斯克、戚風、肉桂捲）、口感評價、更換頻率。
3. **訪店與排隊技巧 (Tips)**：
   - 預約規則（現場登記、IG 私訊、無預約制）、建議到訪時段、熱門品項售完時間點。
4. **關聯主題 (`Topics`)**：
   - 使用雙向連結（如 `[[老屋木造]]`、`[[嘉義布丁專題]]`、`[[工作友善與插座]]`、`[[阿里山咖啡豆]]`）。
5. **歷史更新與矛盾紀錄 (Changelog)**：
   - 記錄隨時間變化的規則（如：低消調整、店休變更、搬遷等）。
6. **參考來源 (Sources)**：
   - 鏈接對應的 `raw/` 原始檔案或來源網址。

## 4. 主題概念頁規格 (`topics/[主題名稱].md`)

主題頁作為知識網的樞紐（Hub），將具備共同特質的店家串聯：
* **常見主題類型**：
  - **氛圍/風格**：`[[老屋木造]]`、`[[昭和復古]]`、`[[文青極簡]]`、`[[庭院綠意]]`
  - **機能/情境**：`[[不限時咖啡]]`、`[[安靜讀書工作]]`、`[[深夜咖啡]]`、`[[適合雙人聊天]]`
  - **風味/甜點**：`[[嘉義布丁特輯]]`、`[[阿里山手沖豆專門]]`、`[[肉桂捲地圖]]`、`[[深焙專門店]]`
* **頁面結構**：
  - 該主題在嘉義的特色綜述。
  - 店家評比對照表（名稱、評分、特色亮點）。
  - 各店家詳細引用區（以反向連結串聯）。

## 5. Agent 核心工作流程 (Workflows)

### 流程 A：資料攝取 (Ingest)
當使用者提供新的 IG 貼文、部落格文章或探店筆記時：
1. **儲存原始檔案**：若使用者上傳文字/文章，將原貌存入 `raw/YYYY-MM-DD-來源名稱.md`。
2. **抽取與標準化**：
   - 萃取 6 大關鍵維度數值與客觀資訊。
   - 若為 IG 貼文，過濾冗餘 hashtag，提煉重點。
3. **更新或新增實體頁 (`cafes/`)**：
   - 若店家已存在：比對新舊資訊，合併心得，若有低消或營業時間變更，記錄於「歷史更新與矛盾紀錄」。
   - 若為新店家：依標準模板建立 `cafes/[店家名稱].md`。
4. **更新關聯主題頁 (`topics/`)**：
   - 檢查該店符合哪些主題（例如有布丁就加入 `[[嘉義布丁專題]]`，安靜高分就加入 `[[安靜讀書工作]]`）。
5. **維護全站索引 (`index.md`)**：
   - 在分類清單或表格中加入新店條目。
6. **寫入日誌 (`log.md`)**：
   - 新增一行：`- [YYYY-MM-DD HH:mm] ingest | [[店家名稱]] | 來源簡述`。

### 流程 B：查詢與合成 (Query & Synthesis)
當使用者詢問推薦、比較或行程安排時：
1. **讀取 Index 與相關頁面**：精準檢索相關店家與主題頁，綜合比對 6 大維度。
2. **產生高價值回答**：不只回答文字，必要時以 Markdown 表格（包含價格、老屋感、咖啡分、甜點分、安靜度、限時）做橫向對照。
3. **知識沉澱（合成回饋）**：若產生了高價值的專題比較（如「嘉義 5 間極安靜手沖老屋評比」），詢問或主動將成果歸檔至 `syntheses/[專題名稱].md`，讓知識永久保留。

### 流程 C：健康檢查 (Lint & Health Check)
定期或依指令巡檢：
1. 孤島頁面（Orphan Pages）：沒有被任何主題或 index 連結的店家頁。
2. 資訊缺失：缺少 6 大維度評分或低消說明的店家。
3. 標籤與連結一致性：檢查雙向連結是否正確。

## 6. 雙向連結 (WikiLinks) 語法準則
- 所有店家一律使用 `[[店家名稱]]`（例如 `[[霜空珈琲]]`，不要使用相對路徑 Markdown 語法）。
- 主題標籤與分類一律連結至對應的 Topic 頁面。
- 務必保持文字自然流暢，使 Obsidian 的 Graph View 能形成緊密有意義的聚類網絡。
